1. Chat — gửi request test

Điền thông tin bên dưới rồi bấm "Gửi request". Mỗi lần gửi = 1 request thật tới API /chat, tạo ra 1 dòng log mới trong data/logs.jsonl kèm correlation_id riêng — dùng cái này để lần theo 1 request cụ thể khi điều tra sự cố.

2. Metrics — số liệu cộng dồn

Tổng hợp từ tất cả request đã gửi trong phiên chạy này (endpoint /metrics). Tự cập nhật mỗi 5 giây. Màu đỏ = đang vi phạm ngưỡng SLO trong config/slo.yaml (vai D).

traffic (tổng số request)-
latency p50 / p95 (ms) — SLO ≤ 3000-
error rate — SLO ≤ 2%-
total cost (USD) — SLO/ngày ≤ 2.5-
tokens in / out-
quality avg — SLO ≥ 0.75-

3. Incidents — giả lập sự cố

Bật 1 sự cố để giả lập hệ thống bị chậm/lỗi/tốn phí, rồi gửi lại chat ở panel 1 — số liệu Metrics và log sẽ đổi theo, dùng để tập điều tra root cause. Nhớ Tắt lại sau khi demo xong.

4. Thông tin request cuối

correlation_id là mã định danh duy nhất của 1 request — dùng để tìm đúng dòng log/trace tương ứng.

correlation_id gần nhất-
file logdata/logs.jsonl
Giao diện này chạy chung tiến trình với API backend (FastAPI serve trực tiếp), không cần server riêng. Các endpoint đang dùng: /chat (gửi tin nhắn), /health (trạng thái), /metrics (số liệu), /incidents/<tên>/enable|disable (bật/tắt sự cố giả lập).
